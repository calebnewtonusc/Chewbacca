# Evidence for competence

Do not claim perfect operation or superiority over every GTM engineer. Define the population, task distribution, environment version, competitors, budgets, and uncertainty that a comparison actually covers.

## Three separate evaluations

1. Navigation: unseen tasks in a disposable workbook, with exact destination-state assertions. Include ambiguous names, missing values, duplicate imports, changed views, timeouts, partial writes, and interrupted sessions. Count silent wrong writes separately from explicit safe stops.
2. GTM judgment: independently labeled accounts and signals, split by company to avoid leakage. Seal the labels before optimization. Report precision, recall, abstention coverage, and cost. Keep development examples separate from the final holdout.
3. Business results: compare matched or randomized eligible cohorts under equal constraints. Declare outcome and maturity window before running. Report held meetings, accepted opportunities, and revenue when observed. Attribution and pipeline forecasts are not realized revenue.

Use a fixed task manifest with hidden evaluator assertions. Have a person other than the generator choose and adjudicate tasks. Compare Chewbacca with the same agent without learned procedures, available native automation, and experienced human operators where those operators consent. Equalize source access and budgets. Report elapsed time, paid cost, interventions, task success, and severe errors separately; do not hide them in one weighted score.

Freeze the primary metric, stopping rule, and sample size rationale before observing final results. Report all assigned tasks, including crashes and unresolved cases. Cluster repeated tasks by template, company, and session when estimating uncertainty. Repeating one easy task is not broad coverage.

For independent identically distributed trials with zero failures in n attempts, the one-sided 95% binomial upper bound on failure probability is 1 - 0.05^(1/n). At n=299 it is about 1%. This does not establish zero failure or transfer to a changed UI. Fifty curated examples are a useful development set, not proof of near-perfect reliability.

Cheap-first cascades must measure false negatives in the cheap stage. Review a random sample of rejected records; otherwise downstream quality can look excellent while recall collapses. Written explanations and self-reported confidence are not calibrated evidence.

## Promotion record

Record task IDs, environment, source access, frozen policy/version, artifacts, independent verdict, actual costs, elapsed time, recovery steps, and remaining uncertainty. A local file hash proves immutability relative to the captured hash, not external authenticity. Retain private source evidence outside the public kit.

Use failure clusters to select the next learning experiment. Choose the cheapest test that distinguishes competing explanations, then rerun the previously failed case and an untouched regression set. A procedure learned from one UI is a hypothesis about transfer, not proof the agent can learn anything.
