# 1000 things wrong with Chewbacca

Written 2026-09-04 against commit `c546aac`, after reading the tree rather than
the README. Three kinds of entry are mixed together on purpose: things that are
broken, things that are fine but unambitious, and things that do not exist yet.

The first few hundred are grounded in specific files. The back half gets more
speculative, and the last category is deliberately unreasonable. Nothing here is
a commitment, it is a menu.

Counts as of this writing: 364 tracked files, 57 slash commands, 21 first-party
skills, 8 hooks, 8 always-on rules, 9 skills with evals, 12 without.

---

## 1. Install and first run

1. `curl | bash` is the front door and nothing verifies a checksum or signature before it executes.
2. There is no pinned release to install against. `main` is the only target, so every new user gets whatever landed an hour ago.
3. No rollback. If setup half-runs, recovery means reading 1,673 lines of bash.
4. The install takes about ten minutes and prints no progress estimate while it runs.
5. The two moments that need a human (the Xcode dialog, the Homebrew password) are explained in the README but not announced by the script at the moment they happen.
6. No `--resume`. A failure at minute nine starts over at minute zero.
7. Nothing writes an install manifest, so `uninstall.sh` is guessing at what setup actually did.
8. Homebrew gets installed unconditionally instead of being offered.
9. No free-disk-space check before starting.
10. No macOS version check before starting.
11. Apple Silicon and Intel paths are never differentiated or tested.
12. Install assumes zsh. A fish or nushell user ends up with a PATH that silently does nothing.
13. There is no `--minimal` profile for someone who wants the standards and none of the Mac control.
14. There is no profile at all: work machine, personal machine, and borrowed machine get identical treatment.
15. Nothing detects an existing `~/.claude/CLAUDE.md` from another kit and offers to merge instead of overwrite.
16. First run never shows the user what it is about to change before it changes it, outside of `--dry-run` that nobody passes.
17. `--dry-run` output is not diffable against a real run.
18. No offline install path, so a bad conference wifi kills the whole thing.
19. Nothing caches downloads, so a retry re-downloads everything.
20. The install has no telemetry, not even local, so nobody knows which step fails most.
21. No install log is written to disk for the user to paste when it breaks.
22. Nothing verifies the machine has the Claude Code CLI before configuring it.
23. There is no way to install for a second user account on the same Mac.
24. There is no containerized or VM install path for someone who wants to try it without commitment.
25. The README's install block is written at an agent, which is clever, and completely opaque to a human skimming it.

## 2. setup.sh itself

26. 1,673 lines of bash in one file. The section guards are enforced by a CI regex, which is a sign the structure is wrong.
27. Five embedded Python heredocs inside a shell script means two languages fail in two ways in one file.
28. CI has to grep for `read` calls to prove the installer is non-interactive. That invariant should be structural, not grepped.
29. A section header inserted in the wrong place once rewrote a live machine's global hooks during an `--only` run. That class of bug is still possible.
30. No unit tests for any individual setup function.
31. `--only` exists but there is no `--skip`.
32. Idempotency is asserted, never tested. Nothing runs setup twice in CI and diffs the result.
33. The script writes to `~/.claude/settings.json` without backing up the previous version by timestamp.
34. There is no `setup --repair` that fixes just what doctor flagged.
35. Nothing pins Homebrew formula versions, so an upstream release can break an install a month from now.
36. Failures inside a section do not abort the section cleanly, they can leave half-state.
37. No dependency graph between sections, so ordering is implicit in file position.
38. The installer cannot be run from a script with a config file, only with flags.
39. `--answers` exists but is undocumented in the README.
40. No way to preview the exact diff to `settings.json` before writing.
41. Nothing warns when it is about to enable `bypassPermissions` on a machine that has company data on it.
42. The installer configures VS Code and Cursor settings without asking whether those editors are even used.
43. There is no post-install summary that says what got skipped and why.
44. No machine-readable exit codes. Everything is 0 or 1.
45. Shell functions and prose comments are interleaved so densely that the file reads as an essay with code in it.
46. Nothing validates that the shell being used to run setup is the shell whose profile it edits.
47. The script cannot install a single skill by name.
48. No `--from-manifest` to reproduce another machine's exact install.
49. The installer never checks whether the user is on a managed device with MDM restrictions.
50. It is one file for what is really six jobs: prereqs, kit files, hooks, MCP, mac tools, shell config.
